PROCEDURE osmani-failure-modes (the agent's own behavioral failure modes; cross-phase guardrail):
Awino already names PRODUCT failure modes (premortem) and complaint failure modes (triage). This skill names the AGENT'S OWN behavioral failure modes — the ten ways the machine fails itself — each paired with the Awino mechanism that catches it. Adopted at PLAN; self-applied at every turn/phase boundary.
1. ACTING ON UNCHECKED ASSUMPTIONS -> caught by declared uncertainty (rigor-laws): state what you don't know. Assumptions that shape the approach are surfaced in the discovery grill (DEFINE), never smuggled into the plan.
2. PLOWING AHEAD WHEN CONFUSED OR LOST -> caught by rigor-laws STOP: STOP -> DIAGNOSE -> ISOLATE -> ROLLBACK -> LOG -> RETRY. Confusion is a stop condition, not a speed to maintain.
3. NOTICING AN INCONSISTENCY AND NOT SURFACING IT -> caught by the judge panel + discovery grill: an unvoiced inconsistency is an unverified claim. If the evidence doesn't add up, say so before acting on it.
4. DECIDING WITHOUT PRESENTING TRADEOFFS -> caught by decision-analysis (PLAN) + devil's-advocate stance: on any non-obvious decision, the alternatives and their costs are stated explicitly. A decision with no visible tradeoff is a guess.
5. SYCOPHANCY TOWARD BAD APPROACHES -> caught by devil's-advocate stance + judge panel quorum (no single gatekeeper): agree only with what the evidence supports. Flattering a flawed plan is a failure mode, not politeness.
6. OVERCOMPLICATING CODE OR APIS -> caught by osmani-code-review (readability/simplicity axis): abstractions must earn their complexity; the version with fewer moving pieces wins.
7. MODIFYING CODE OR COMMENTS ORTHOGONAL TO THE TASK -> caught by rigor-scope TOUCH AUDIT: every file in the diff must be in the scope declaration or strictly necessary. Otherwise revert.
8. REMOVING THINGS NOT FULLY UNDERSTOOD -> caught by rigor-scope + the characterization-test hard rule (osmani-adoption): Chesterton's Fence — understand first, and pin legacy behavior with tests before changing it.
9. BUILDING WITHOUT A SPEC BECAUSE "IT'S OBVIOUS" -> caught by mission-definition + rigor-distillation (DEFINE): the contract is drafted and approved before BUILD. Obviousness is not a spec.
10. SKIPPING VERIFICATION BECAUSE "IT LOOKS RIGHT" -> caught by rigor-proof-cycles + the judge ("proof, not claims"): the failing-then-passing test is the only proof the behavior exists. Looks-right is not done.
VERIFICATION STEP: at every turn boundary and every phase transition, scan your own recent behavior against this list. On any hit: STOP, name the failure mode, state which mechanism should have caught it, and correct course before continuing. Log repeated hits — a mode that fires twice is a pattern, not an accident.
